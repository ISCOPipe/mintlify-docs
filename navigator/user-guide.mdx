NaviGator models every trip as a two-phase lifecycle: **Planning** (before any activities exist) and **Execution** (after stops are assigned as workflow activities). The UI is intentionally split along this line, so understanding the phase you are in determines which controls are available and where edits are persisted.

This guide is grounded in the actual onboarding tour (`src/tour/onboardingTour.ts`) and the planning-vs-execution document (`markdown/planning-vs-execution.md`). It describes only features that exist in the codebase.

## Planning Phase: Build the Itinerary

### 1. Load Nearby Places

Open the app and press **Search Area** (desktop header or mobile actions menu). The app queries the Navigator Services API for enabled geographic layers inside the current map viewport. Filters and result limits can exclude records; the map does not guarantee that every matching record is displayed. Results appear as colored pins on the map and as cards in the side panel.

- **Customers**: blue pins
- **Plants**: green pins
- **Projects**: teal pins
- **Landfills**: brown pins
- **Capital Projects**: purple pins
- **Opportunities**: orange pins

You can filter by market segment, SIC code, PEC timing, sales stage, and more via the **Settings** panel (gear icon).

### 2. Add Stops

Click any pin to open its detail card, then press **Add as Stop**. The app reverse-geocodes the address, looks up the timezone by coordinates, and appends the stop to your itinerary. If you drop a pin manually, the tour will auto-snap it to the nearest road so it is routable.

Supported stop sources (from `src/types/stop.ts`):

| Source | How Added |
| --- | --- |
| Customer | Click pin or search by name |
| Plant | Click pin or search by name |
| Project | Click pin or search by name |
| Landfill | Click pin or search by name |
| Capital Project | Click pin or search by name |
| Opportunity / Quote | Click opportunity pin, then select a child quote or customer |
| Manual Address | AddressSearch bar or dropped pin |
| Workflow Task | Pull from the Activities tab (see Execution) |

### 3. Reorder and Optimize

Stops can be reordered by drag-and-drop in the **Stops** sidebar (desktop) or the **Itinerary** panel (mobile). Press **Optimize** to run the route optimizer, which:

1. Clusters nearby stops geographically (`clusterRoutingService.ts`)
2. Uses Mapbox Optimization API for each cluster (`routeOptimizationService.ts`)
3. Respects fixed-time appointments and day boundaries (`scheduleCalculator.ts`)

If you have fixed-time appointments (e.g., a lunch meeting at 12:00), tick **Scheduled Visit** on that stop and set the time. The optimizer will anchor that stop and arrange flexible stops around it.

### 4. Set Visit Details

Expand any stop card to set:

- **Contacts**: Search HubSpot contacts or create a new one. These carry through to the activity when assigned.
- **Visit Reason**: Required before assignment. This becomes the activity type in Pipeline.
- **Scheduled Visit**: Optional fixed-time appointment.
- **Visit Time (min)**: How long you plan to stay (default 15 minutes).

### 5. Save or Export

Before assigning, you can:

- **Save Itinerary**: Stores the full itinerary to the backend with a name and document ID (`itinerarySaveService.ts`).
- **Export to Outlook**: Generates an `.ics` calendar file with all stops and travel times (`exportService.ts`).
- **Export to Google Maps**: Opens a Google Maps directions link with all waypoints.
- **Export to PDF**: Generates a printable itinerary with a static map image.

## Execution Phase: Run the Trip

### 1. Pull Assigned Activities

Switch to the **Activities** tab to see series assigned to you. Each series is a trip planned by a manager or by yourself. Press **Work on this** to activate a series, or **Add Stop** to pull an individual activity into the builder.

When you pull a stop, it arrives with its `wfactId` (workflow activity ID), scheduled time, contacts, and visit reason already populated from the backend.

### 2. Close Out Stops

After visiting a stop, expand its card and press **Complete Stop** (or **Defer Stop** if no one was available). The close flow (`CloseStopModal.tsx`) requires:

- A note describing what happened
- Confirmation of which contacts were actually met (you can add or remove contacts)

Closing with contacts marks the activity as completed in Pipeline. Closing without contacts defers it. The stop card grays out once closed.

### 3. Real-Time Edits During Execution

Every edit to an activity-backed stop (`wfactId` set) writes through to the backend immediately:

| Edit | API Call |
| --- | --- |
| Stop name | `editActivityName` |
| Scheduled time / visit time | `useActivityScheduleSync` -> `editActivitySchedule` |
| Contact added/removed | `addActivityContacts` / `removeActivityContacts` |
| Close-out (note + status) | `UnifiedStopCard.finishClose` |

## Desktop vs Mobile Layout

| Feature | Desktop | Mobile |
| --- | --- | --- |
| Planning sidebar | Left **Stops** panel | **Itinerary** tab (combined) |
| Generated schedule | Right **Itinerary** panel | **Itinerary** tab (combined) |
| Map | Center, always visible | **Map** tab |
| Activities | **Activities** tab | **Activities** tab |
| Settings | Gear icon in header | Gear icon in bottom nav |
| Search | Header bar | Search drawer |

The mobile **Itinerary** tab uses `UnifiedStopCard` with `executeOnly={false}`, so it supports both planning and execution in one card. The desktop right panel uses `executeOnly={true}` when rendering assigned activities, hiding planning-only controls like the stop name editor.

## Add a point of interest

A point of interest (POI) is a named place from address search, such as a business or venue. It is not automatically an ISCO customer.

1. Search for the place and select its POI result.
2. In **Add a Location**, wait for the nearby-record check to finish. You cannot save while it is running.
3. Review **Use as stop basis**. The app searches within **500 meters** and shows candidate distances in rounded feet.
4. Keep the POI, or select a nearby customer, plant, project, landfill, strategic partnership, or opportunity. A selected ISCO record supplies its own identity and coordinates instead of the POI.
5. If you keep the POI, enter a location name. You can also select a customer, contact, and reason for the stop.
6. To request a customer address update, select a customer and an address-request type. This submits a request; it does not immediately update the customer master record.
7. Save the location, then continue planning the trip.

If no nearby records are found, you can keep the POI. If the check fails, the app tells you and still lets you use the POI. Do not assume a failed search proved there are no matching records.

## Open and dismiss map cards

1. Search the area, then select a result pin. On desktop, rest the pointer briefly on the pin before clicking; the app ignores hurried mouse clicks to avoid opening a card while you pan. Touch, pen, and keyboard activation do not require this pause.
2. If you see a numbered cluster, select it to zoom toward its individual pins. A cluster count is a count of loaded map results, not a total from the source system.
3. Review the card before adding a stop. On mobile, the card appears over the page, above the bottom tab bar, so neither the map container nor the tab bar clips it. Scroll its content when needed. The map legend also floats above the tab bar on mobile.
4. Use the card's close control, or press **Escape** with a keyboard. When a dialog is open above the map, close that dialog first.
5. If the wrong record opens or pins overlap, use the result list and its globe control to focus the intended pin. Recheck the name and record type before choosing **Add as Stop**.

These interactions come from `src/components/geoMarkers/shared.ts`, `src/components/map/clusterLayers.ts`, and `src/components/MapView.tsx`. The [app's detailed manual](https://github.com/ISCOPipe/itinerary-builder/blob/6ad7e8280e564260a8f459ae2864eb1859e40ec6/markdown/USER_MANUAL.md) covers additional search, schedule, and mobile controls. Its screenshots and example records are not a guarantee of what your account can see.

## Control map results

Use settings to choose opportunity stages: New Opportunity, In Design, Project Bidding, Provided Quote, Contractor Awarded, and PO Pending. Customer filtering by opportunity stage is a separate option; showing an opportunity layer does not necessarily narrow customer pins.

If results appear incomplete, narrow the area and review enabled layers, stages, and recent-date filters. The API caps result sets; `/geo-activities` accepts at most 1000 activities per request. See [API search constraints](/navigator/services-api).

## Navigator Games

NaviGator includes four optional, hidden mini-games. They are not part of the planning or execution workflow, and you never need them to build or run a trip. Each game opens as a dialog over the app with a shared header that has **Restart** and **Close** controls.

To open a game, type its trigger phrase while the main app has keyboard focus (not while typing in a search box or form field):

| Game | Trigger | How to play |
| --- | --- | --- |
| Front 9 golf | `iscochampionship` | Pick a target and club, set direction and distance, and account for wind and the projected landing across nine holes. |
| HDPE Stack | `hdpehdpe` | Left/Right arrows move the piece, Up or Z rotates, Space drops, P pauses, and R restarts. On-screen buttons provide touch alternatives. |
| Ten-pin bowling | `bowlingbowling` | Aim and release the ball, apply spin when available, and follow frames on the scorecard. |
| Candlepin bowling | `candlepinbowling` | Use the same bowling controls with the candlepin rules and scoring shown in the game. |

### Rules and limits

- **One game at a time.** Typing a second trigger while a game is open or loading does nothing. Close the current game first.
- **15-minute daily limit.** All four games share one 15-minute budget per day. NaviGator counts only time spent inside the working hours set in **Settings** (daily start and end time). Time outside working hours is not counted. If your working hours are missing or the end time is not after the start time, the games have no limit.
- **When the limit runs out.** NaviGator shows a notice that the day's game time is used up. You can finish the game in progress, but you cannot restart it or open another game until working hours end. Usage is stored on the current device and browser.
- **Bowling loads on demand.** The bowling games load their 3D graphics and physics only when you type a bowling trigger, so they do not slow down normal app startup. Expect a short delay the first time.

### Leaderboards

Each game has a shared leaderboard that Navigator Services stores through the `/navigator_gamify` endpoints. When you finish a game while signed in, NaviGator submits your score and shows your best result on the leaderboard. If saving fails, the game tells you and you can still close or restart it.

Front 9 golf has two extra leaderboard rules:

- **All nine holes required.** Only rounds that play every hole are submitted. A partial round shows "Only rounds that play all nine holes go on the leaderboard."
- **Assisted rounds are excluded.** Golf includes two hidden assists. Type `gopher`, or tap the ball five times quickly, to have a gopher carry your next full swing to the cup. Type `eagle`, or tap any bunker five times quickly, to have an eagle do the same. Using either assist on any hole keeps that round off the leaderboard.

## Onboarding tour

New users can launch the guided tour from **Settings > Advanced > Replay Tutorial**. The tour (`src/tour/onboardingTour.ts`) walks through:

1. Loading the map with Search Area
2. Clicking the nearest pin and adding it as a stop
3. Expanding the stop card to see contacts, visit reason, and scheduled visit
4. Assigning the day as activities
5. Opening settings to configure working hours, layers, and route type

The tour is interactive: most steps wait for the user to perform the action rather than just narrating it. A "Skip step" button is always available.
