This page is a guided tour of the `itinerary-builder` codebase for engineers who need to find, change, or debug a feature. Every claim is grounded in the actual source files.

## Entry Points

### `src/main.tsx`

The React bootstrap file performs initialization in this order:

1. **APM initialization** (`initializeApm()`) — async, deliberately not awaited so startup never blocks
2. **Version check** (`checkVersionAndClearIfNeeded()`) — compares `CURRENT_APP_VERSION` against localStorage; clears storage on mismatch so old schema data does not crash the app
3. **MSAL initialization** (`msalInstance.initialize()`) — sets up Azure Entra ID auth
4. **Redirect handling** (`handleRedirectPromise()`) — processes the OAuth redirect, sets the active account, or triggers `loginRedirect` if no account exists
5. **React render** — mounts `<App />` inside `<MsalProvider>` and `<ApmErrorBoundary>`

An event callback listens for `EventType.LOGIN_SUCCESS` to set the active account from the payload.

### `src/App.tsx`

The top-level orchestrator (~131KB, so it is large by necessity). It:

- Initializes all custom hooks (`useStops`, `useSchedule`, `useGeoData`, `useAppState`, etc.)
- Composes the responsive layout: `AppHeader`, `StopsSidebar` (desktop left), `MapView` (center), `ScheduleView` / `ItineraryPanel` (desktop right / mobile tabs)
- Handles high-level event handlers: adding stops from geo queries, address search, assignment, export, save/load itinerary
- Manages mobile tab state (`MobileNavigation`)
- Lazy-loads heavy components (`MapView`, `AppModals`, `WeatherPanel`, `OpportunityLinksModal`) to reduce initial bundle size

## State Management: Custom Hooks

The app uses React hooks for all state. No Redux, Zustand, or external store.

### `src/hooks/useStops.ts`

The primary stop state hook. Returns:

```typescript
{
  stops: Stop[];
  expandedIdx: number | null;
  isLoaded: boolean;
  addStop, removeStop, updateStop, toggleExpanded, reorderStops,
  loadStops, clearStops,
  // Conflict handling for scheduled-stop time overlaps
  conflictContext, resolveConflict, cancelConflict,
}
```

- Stops are loaded from `localStorage` on mount via `loadItineraryFromStorage()`
- Every mutation auto-saves back to `localStorage`
- Detects fixed-time conflicts using `timeConflictValidation.ts` and surfaces a modal before applying the edit

### `src/hooks/useSchedule.ts`

Auto-calculates the schedule whenever stops or config change. Key behaviors:

- Builds a **route signature** from stop coordinates and order; only fetches a new Mapbox Matrix when the signature changes
- Caches the routing matrix to avoid redundant API calls when only dwell times change
- Calls `ScheduleCalculator.calculateWithWarnings()` to produce `ScheduleItem[]` with day boundaries, fixed-time handling, and timezone-aware formatting

### `src/hooks/useGeoData.ts`

Fetches geo customers, plants, projects, landfills, cap projects, and opportunities within the current isochrone or search polygon. Returns:

```typescript
{
  customerResults, plantResults, projectResults, landfillResults,
  capProjectResults, opportunityResults,
  isFetching, triggerQuery,
  // Filter options with counts (for UI dropdowns)
  customerOptions, plantOptions, projectOptions, /* ... */
}
```

### `src/hooks/useAppState.ts`

Centralized app state and stop creation handlers. Key exports:

```typescript
{
  createBaseStop,           // async factory with timezone + reverse geocode
  handleAddCustomerStop,    // enriches with recent activities, opportunity counts
  handleAddPlantStop,
  handleAddProjectStop,
  handleAddLandfillStop,
  handleAddCapProjectStop,
  handleAddOpportunityPointStop,  // adds a quote/customer from an opportunity
  handleAddTaskStop,        // pulls a workflow activity into the builder
  handleAssignActivities,   // assigns stops to team or individual employee
  activeCustomerId, setActiveCustomerId,
  routeCorridorPolygon, setRouteCorridorPolygon,
}
```

`setOriginIfFirstStop` automatically sets the itinerary origin to the user's current location when the first stop is added.

## PWA Behavior

Configured in `vite.config.ts` via `vite-plugin-pwa`:

- **Manifest**: `name: "ISCO NaviGator"`, `short_name: "NaviGator"`, standalone display, portrait-primary orientation
- **Icons**: `192.png`, `512.png` (also maskable)
- **Assets**: `navigator3.png`, `naviGator-intro-once.gif`, `naviGator-blinking-loop.gif`, `isco_logo.png`
- **Workbox**: `navigateFallback: 'index.html'` for SPA routing; API paths excluded from fallback
- **Runtime caching**: Mapbox API calls cached with NetworkFirst, 5-minute TTL, max 50 entries

The service worker is generated at build time; no custom service worker source file is maintained.

## APM Instrumentation

Elastic APM RUM is initialized in `main.tsx` before React mounts. Key design decisions from `src/config/apm.ts`:

- **Opt-in only**: `VITE_APM_ACTIVE` must be exactly `"true"`; disabled by default
- **No credentials in the bundle**: The browser RUM agent does not authenticate; access is controlled server-side via `rum.enabled` and CORS `allow_origins`
- **Dynamic import**: The agent is loaded via `import('@elastic/apm-rum')` so it is code-split into its own chunk and never fetched when APM is off
- **Fail closed**: If `VITE_APM_ACTIVE=true` but `VITE_APM_SERVER_URL` is missing, initialization is refused rather than defaulting to an unintended endpoint
- **Distributed tracing**: `API_BASE_URL` and `location.origin` are registered as `distributedTracingOrigins`

APM actions are tracked via `apmActions.ts` with typed domains:

```typescript
// Example: tracking a stop add
trackStopAction('add_customer', { stopName: 'Acme Corp', stopSource: 'customer' });

// Example: tracking a route optimization
trackRouteAction('optimize', { stopCount: 5 });

// Example: tracking an API call
const tx = trackApiAction('mapbox_matrix', { endpoint: 'directions-matrix/v1/mapbox/driving', method: 'GET' });
tx.end({ api_status_code: 200 });
```

## Logging

`src/utils/logger.ts` provides an environment-aware logger:

- `logger.debug()` and `logger.info()` only log in development (`import.meta.env.DEV`)
- `logger.warn()` and `logger.error()` always log, even in production

This replaces raw `console.log` calls throughout the codebase.

## Data Flow Summary

```text
User Action (click pin, add stop, reorder, assign)
        |
        v
App.tsx event handler
        |
        v
useAppState handler (createBaseStop + addStop)
        |
        v
useStops (persist to localStorage)
        |
        v
useSchedule (detect change -> fetch matrix -> calculate)
        |
        v
ScheduleView / ItineraryPanel re-render
        |
        v
MapView (routeOrchestrator -> draw route + markers)
```

For execution-phase edits:

```text
User edits stop (contacts, schedule, close-out)
        |
        v
UnifiedStopCard -> activity service (addActivityContacts, editActivitySchedule, finishClose)
        |
        v
Navigator Services API -> Pipeline workflow tables
        |
        v
useStops update (local state + localStorage)
```
