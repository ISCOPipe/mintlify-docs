The Parrot worker is an AWS Chalice application (`quote-builder-worker`) that runs as an SQS-triggered Lambda. Configuration flows from SSM Parameter Store at cold start, with environment variable fallbacks for local development. Unless a path starts with `quote_builder/`, worker paths on this page are relative to the `quote_builder_aws/quote_builder/` application directory.

<Warning>
  This repo contains committed secrets (API keys, DB passwords, tokens). Never commit live values. Use SSM SecureString parameters or local `.env` files. Document setting names only.
</Warning>

### Empty-by-default Values

These keys are set to `""` in `config.json` because their real values come from SSM at cold start:

| Key | SSM Source | Purpose |
| --- | --- | --- |
| `JOBS_BUCKET` | `/parrot/{stage}/uploads-bucket` | S3 bucket for job inputs/results |
| `ORCHESTRATION_API_URL` | `/parrot/{stage}/orchestration-api-url` | Base URL for O->S callbacks |
| `OPENROUTER_API_KEY` | `/parrot/openrouter-api-key` | LLM API key |

When `ORCHESTRATION_API_URL` is empty, the worker writes directly to DynamoDB instead of sending HTTP callbacks. This does not make the run offline or prevent writes to real resources.

**File:** `chalicelib/aws/ssm_config.py`

### Resolution Order

SSMConfig resolves each key in this priority:

1. SSM Parameter Store value (cached at cold start)
2. Environment variable (from `config.json` or local `.env`)
3. Default supplied by the caller
4. Mapped default (from `_PARAM_MAP`)

After loading, `cfg.inject_env_vars()` pushes resolved SSM values back into `os.environ` so downstream code that reads env vars directly (e.g. `OpenRouterClient`) gets the SSM value.

## LLM Client Configuration

The `OpenRouterClient` (`chalicelib/llm/openrouter.py`) is configured entirely via environment variables:

| Variable | Default | Description |
| --- | --- | --- |
| `OPENROUTER_API_KEY` | (required) | Bearer token for OpenRouter API |
| `OPENROUTER_MODEL` | `google/gemini-3-flash-preview` | Default model for all LLM calls |
| `OPENROUTER_BASE_URL` | `https://openrouter.ai/api/v1` | API endpoint |
| `OPENROUTER_HTTP_REFERER` | (none) | Optional HTTP-Referer header |
| `OPENROUTER_X_TITLE` | (none) | Optional X-Title header |
| `OPENROUTER_REASONING_EFFORT` | (none) | Reasoning effort for supported models |
| `OPENROUTER_MAX_IN_FLIGHT_PER_JOB` | `100` | Semaphore limit for async LLM calls |

**Key behaviors:**

- Uses a shared `urllib3.PoolManager` with `maxsize=32` and disabled retries at the transport level (pipeline handles its own retry/escalation).
- Connection-level failures (handshake timeout, reset) get 3 jittered retries with exponential backoff starting at 0.75s.
- `session_id` is set to the `job_id` so all LLM calls for a job group together in OpenRouter activity logs.
- GPT-OSS models automatically get `reasoning_effort: "low"` if not explicitly set.

## Pipeline Runner Modes

The `PipelineRunner` (`chalicelib/pipeline/runner.py`) supports several operational modes:

| Mode | How to Enable | Effect |
| --- | --- | --- |
| `extraction_only` | Pass `extraction_only=True` to runner | Skips all matching stages after extraction |
| `cost_mode` | Pass `cost_mode=True` to runner | Resolves dollar costs from OpenRouter generation IDs at end |
| `inventory` | Pass `mode="inventory"` to runner | Uses strict SKU reconciliation prompts instead of RFQ matching |
| `llm_enabled=false` | Pass `llm_enabled=False` to runner | Disables all LLM features; deterministic fallback paths only |

When `llm_enabled=False`:

- Translation is skipped
- Segmentation uses regex fallback
- Structurer passes through raw lines
- Filter uses deterministic regex
- Junk filter is disabled
- Match selection is disabled
- Context resolve is disabled
- Match confirm marks all as NO-MATCH
- Cohere rerank is disabled

---

## Cost Tracking

When `cost_mode=True`, the pipeline resolves actual dollar costs from OpenRouter after completion:

1. `CostTracker` collects all `generation_id` values from OpenRouter calls.
2. `OpenRouterClient.resolve_costs_batch()` queries `/v1/generation?id={id}` concurrently (default 10 workers).
3. Costs are mapped back to each pipeline stage.

Per-step cost data includes:

- API call count
- Prompt, completion, and total tokens
- Cohere search units
- Wall-clock seconds
- Dollar cost (when resolved)

**File:** `chalicelib/pipeline/cost.py`
