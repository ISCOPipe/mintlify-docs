The Parrot worker (`iscopipe/quote_builder_aws`) is a Python 3.12 Chalice app that processes RFQ jobs from SQS. You can run the full matching pipeline locally against sample files before deploying.

<Warning>
  The repository contains committed secrets (API keys, AWS credentials, connection strings). Never copy secret values into the docs or commit them. Use a local `.env` file and the team's secret store for real values.
</Warning>

## Requirements

- Python 3.12 or later
- [uv](https://docs.astral.sh/uv/)
- AWS credentials with read access to SSM parameters under `/parrot/dev/`
- API keys for OpenRouter, Cohere, and Cloudflare Workers AI (get these from your team lead)

## Set up

<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/iscopipe/quote_builder_aws.git
    cd quote_builder_aws
    ```
  </Step>
  <Step title="Install uv and create the virtual environment">
    Run the bootstrap script, which installs uv if missing, creates `.venv`, and installs the core dependencies:

    ```bash
    chmod +x setup_test_gui.sh
    ./setup_test_gui.sh
    ```

    The script writes `chalice`, `boto3`, `openpyxl`, and `textual` into the venv. Full dependencies are defined in `pyproject.toml` and managed by `uv sync`.
  </Step>
  <Step title="Create a .env file">
    Create `.env` in the repo root. Local scripts load it automatically, and any missing values are pulled from SSM.

    ```bash .env
    OPENROUTER_API_KEY=
    COHERE_API_KEY=
    CLOUDFLARE_ACCOUNT_ID=
    CLOUDFLARE_API_TOKEN=
    
    # Optional overrides
    # OPENROUTER_MODEL=google/gemini-3-flash-preview
    # QUOTE_BUILDER_LLM_DEBUG=1
    # JOBS_BUCKET=quote-builder-jobs-201014308786-us-east-2
    # JOBS_TABLE=jobs-table
    # RESULTS_TABLE=job-results-table
    ```

    The `.env.example` generated by `setup_test_gui.sh` lists the same keys.
  </Step>
  <Step title="Bootstrap SSM parameters">
    The worker loads stage-scoped config from AWS SSM Parameter Store at cold start. The loader (`chalicelib/aws/ssm_config.py`) reads everything under the prefix and falls back to environment variables when SSM is unavailable.

    Required SSM paths (names only, values come from the team's secret store):

    | SSM path | Env fallback | Purpose |
    | --- | --- | --- |
    | `/parrot/openrouter-api-key` | `OPENROUTER_API_KEY` | LLM provider key |
    | `/parrot/openrouter-model` | `OPENROUTER_MODEL` | Model slug (default `google/gemini-3-flash-preview`) |
    | `/parrot/cohere-api-key` | `COHERE_API_KEY` | Rerank API key |
    | `/parrot/cloudflare-account-id` | `CLOUDFLARE_ACCOUNT_ID` | Workers AI account |
    | `/parrot/cloudflare-api-token` | `CLOUDFLARE_API_TOKEN` | Workers AI token |
    | `/parrot/llama-parse-key` | `LLAMA_PARSE_API_KEY` | Document parser key |
    | `/parrot/es/api_key` | `ES_API_KEY` | Elasticsearch API key |
    | `/parrot/es/api_url` | `ES_URL` | Elasticsearch endpoint |
    | `/parrot/jobs-table` | `JOBS_TABLE` | DynamoDB jobs table |
    | `/parrot/jobs-table-v2` | `JOBS_TABLE_V2` | DynamoDB v2 jobs table |
    | `/parrot/uploads-bucket` | `JOBS_BUCKET` | S3 uploads bucket |
    | `/parrot/dispatch-queue-name` | `DISPATCH_QUEUE` | SQS dispatch queue |
    | `/parrot/orchestration-api-url` | `ORCHESTRATION_API_URL` | Orchestration API base URL |
    | `/parrot/orchestration_service_contract/api_key` | `ORCHESTRATION_API_KEY` | Orchestration API key |

    Stage-scoped keys (jobs tables, queues, API version) are read from the stage prefix (e.g. `/parrot/dev/`). All other keys are read from the base `/parrot/` path.
  </Step>
  <Step title="Run the pipeline locally">
    Launch the interactive TUI to pick a fixture and run the full pipeline:

    ```bash
    source .venv/bin/activate
    python tests/test_pipeline_gui.py
    ```

    Add `--pretty` for a tabular result view, or `--cost` to resolve OpenRouter spend:

    ```bash
    python tests/test_pipeline_gui.py --pretty
    python tests/test_pipeline_gui.py --pretty --cost
    ```

    To simulate the full SQS-to-worker flow with a fake SQS record and stub DynamoDB client:

    ```bash
    uv run python tests/dry_run_worker.py
    ```

    The dry-run script lists available fixtures in `tests/fixtures/`, prompts you to pick one, then runs both dev mode (DynamoDB writes) and prod mode (HTTP callbacks to a fake orchestration URL). Output is written to `tests/dry_run_output/`.
  </Step>
</Steps>

## Deploy

The Chalice app lives in `quote_builder/`. Stages are defined in `quote_builder/.chalice/config.json`:

| Stage | SSM prefix | Queue | Jobs table |
| --- | --- | --- | --- |
| `dev` | `/parrot/dev/` | `parrot-job-dispatch-dev` | `parrot-jobs-dev` |
| `prod` | `/parrot/` | `parrot-job-dispatch` | `parrot-jobs` |

Deploy a stage:

```bash
cd quote_builder
chalice deploy --stage dev
```

<Warning>
  Deploy to `dev` and verify a job end to end before deploying to `prod`.
</Warning>

The repo does not contain a deploy script. Use `chalice deploy` directly.
