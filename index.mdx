These guides cover five distinct products: Pipeline, Pip, Parrot, QMD, and ISCO NaviGator. Start with the product you use or maintain. Integrations connect them, but they do not share one runtime or development setup.

## Choose a starting point

- **Use an application:** follow the [Pipeline workflows](/pipeline/workflows), [Parrot user guide](/parrot/user-guide), [QMD field guide](/qmd/field-app), or [ISCO NaviGator user guide](/navigator/user-guide).
- **Set up a development environment:** follow the [quickstart](/quickstart), then the setup page for your product.
- **Trace a request:** start with the [architecture](/architecture), then open the product API reference.
- **Find a supporting repository:** use the [source map](/source-map).

## Common terms

A **repository** holds one part of the source code. A **service** runs behind an application and handles requests. An **API endpoint** is a URL and HTTP method that a service accepts.

**Pip** is the assistant and knowledge system; **Pipeline** is the intranet. In Parrot, a **job** is one uploaded request and its extracted lines. A **candidate** is a suggested catalog product, not a confirmed selection. In ISCO NaviGator, an **itinerary** is a saved plan; an **activity** is a visit assigned for execution. In QMD, a **joint** is a recorded fusion operation.
