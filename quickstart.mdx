## 1. Get access

Confirm that you can read the required repositories in the `ISCOPipe` GitHub organization. Obtain development configuration and network access through your team. Do not copy credentials from source files or reuse production data to test a write operation.

Install Git and configure GitHub authentication. Then create a workspace:

```bash
mkdir isco
cd isco
```

## 2. Clone only the required repositories

| Product | Repositories | Next step |
| --- | --- | --- |
| Pipeline | `pipeline`; add `services_hot_reload` for API work | [Local setup](/pipeline/local-setup) |
| Parrot | `pipeline`, `quote_builder_orchestration`, `quote_builder_aws` | [Worker setup](/parrot/worker-setup) and [orchestration setup](/parrot/orchestration-setup) |
| QMD | `qmd_weld_app_windows`, `qmd_weld_app_web`, `qmd_weld_app_api` | [QMD setup](/qmd/setup) |
| ISCO NaviGator | `itinerary-builder`, `navigator_services` | [App setup](/navigator/app-setup) and [services setup](/navigator/services-setup) |

For example, clone the ISCO NaviGator pair:

```bash
git clone https://github.com/ISCOPipe/itinerary-builder.git
git clone https://github.com/ISCOPipe/navigator_services.git
```

The [source map](/source-map) lists supporting repositories and the branches used to verify these guides.

## 3. Match the toolchain to the application

- **Pipeline:** PHP, Composer, required PHP extensions, and Node.js for the React bundles. The existing Windows setup expects connection includes outside the repository. The container setup is a separate path, not proof that every Windows page works unchanged on Linux.
- **TypeScript services:** Node.js and npm. Use the repository's lockfile with `npm ci` and check its current runtime requirements.
- **ISCO NaviGator frontend:** a Node.js version supported by the installed Vite toolchain. Its Vite 7 dependencies require a newer runtime than an arbitrary Node 20 installation.
- **Parrot Python services:** Python 3.12 or later and `uv` for the worker. AWS access and external providers are needed for a full processing run.
- **QMD:** Windows and Visual Studio with the workloads required by each .NET Framework or UWP solution. Do not substitute a portable `dotnet build` command without checking the project targets.

## 4. Start and check one layer at a time

1. Install dependencies from the product's setup guide.
2. Add local configuration using placeholder templates where available. Check that secret files remain untracked.
3. Build the changed component before starting it.
4. Confirm its local URL and port from the startup output.
5. Point the frontend at the intended development backend before signing in.
6. Use a read-only request or approved test record to check the connection.

<Warning>
Both TypeScript APIs default to port `4443`. If you run them on the same machine, assign different `PORT` values and update the client base URLs. They are separate services with different authentication behavior.
</Warning>

## When setup fails

- **Dependency install fails:** check your Node or Python version before changing the lockfile.
- **Page loads but data does not:** check backend URL, network access, credentials, CORS, and browser request errors.
- **API returns 401:** use the token type expected by that service. A Parrot API key is not a NaviGator Azure access token.
- **QMD upload fails:** preserve local joints and follow the [field-app recovery steps](/qmd/field-app).
