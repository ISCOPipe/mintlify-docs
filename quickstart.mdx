Every ISCO project lives in the `iscopipe` GitHub organization. This guide gets you from zero to a machine with all Pipeline, Parrot, and QMD repositories cloned, so you can move on to each project's setup guide.

## Prerequisites

- A GitHub account added to the `iscopipe` organization (ask an org admin)
- [Git](https://git-scm.com/downloads) and either SSH keys or the GitHub CLI configured for authentication
- Credentials for the systems you will work with (SQL Server, AWS, Azure AD). Get these from your team lead; they are never stored in these docs.

## Clone the repositories

<Steps>
  <Step title="Create a workspace folder">
    ```bash
    mkdir isco && cd isco
    ```
  </Step>
  <Step title="Clone the repositories you need">
    <CodeGroup>

    ```bash Pipeline
    git clone https://github.com/iscopipe/pipeline.git
    ```

    ```bash Parrot
    # The Parrot UI lives in the pipeline repo
    git clone https://github.com/iscopipe/pipeline.git
    git clone https://github.com/iscopipe/quote_builder_orchestration.git
    git clone https://github.com/iscopipe/quote_builder_aws.git
    ```

    ```bash QMD
    git clone https://github.com/iscopipe/qmd_weld_app_web.git
    git clone https://github.com/iscopipe/qmd_weld_app_api.git
    git clone https://github.com/iscopipe/qmd_weld_app_windows.git
    ```

    </CodeGroup>
  </Step>
  <Step title="Follow the project setup guide">
    - [Pipeline local setup](/pipeline/local-setup)
    - [Parrot worker setup](/parrot/worker-setup) and [orchestration API setup](/parrot/orchestration-setup)
    - [QMD setup](/qmd/setup)
  </Step>
</Steps>

## Install shared tooling

| Tool | Needed for |
| --- | --- |
| PHP 8.2+, Composer | Pipeline |
| Node.js 20 and npm | Pipeline React build, Parrot UI |
| Python 3.12 and [uv](https://docs.astral.sh/uv/) | Parrot worker and orchestration |
| AWS CLI with ISCO credentials | Parrot (SSM, DynamoDB, S3, SQS) |
| Visual Studio with ASP.NET and UWP workloads | QMD |

<Warning>
  Never commit credentials. Keep secrets in local `.env` files, AWS SSM, or untracked config, and confirm they are covered by `.gitignore` before you push.
</Warning>
