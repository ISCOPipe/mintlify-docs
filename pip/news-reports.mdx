`pip-news-feed-report-service` is a separate Culvert lead-feed service. It fetches news, analyzes and ranks leads, and stores reports for human review. It does not use Pip's conversational route or share its Chalice runtime. The inspected integration uses `scheduled_jobs` to trigger a run and a Pipeline emailer callback to deliver it. Its repository name alone does not establish a chat integration.

## Review the report, not just its score

The service separates model labels from deterministic scoring. Its configuration controls weights, tiers, and feeds. Reports distinguish explicit source claims from inferred sales interpretation. Check the supporting article and warning badges before acting; the report does not contact a prospect or create a HubSpot opportunity.

## News-feed reports

`pip-news-feed-report-service` runs asynchronous reports. Use bearer authentication for protected routes. `POST /runs` accepts the report date and returns `202`; the run status and download routes let a client follow the result. The service also exposes `/healthz`.

1. Submit one run for the intended date.
2. Save its returned identifier.
3. Poll its status rather than resubmitting while it works.
4. Download the stored result when the run is complete.
5. Check notification records separately if email delivery matters.

A completed run means the report was stored, not that email reached a recipient. Notification retries are capped at three; delivery is not exactly once. Runs older than three hours can be treated as stale. The render path can send email. A dry run can still call paid services and store output, so it is not an offline check.

## Prepare local development

Use Python 3.10 or later for the project; the Docker image uses Python 3.12. From the repository root, create an isolated environment and install the package with its development extra using `python -m pip install -e '.[dev]'`. Run offline checks with `python -m pytest -q`.

The image starts `python -m uvicorn api.main:app --host 0.0.0.0 --port 8000`. For a local-only development listener, use `python -m uvicorn api.main:app --host 127.0.0.1 --port 8000` after setting approved local configuration. Starting the API is not permission to submit a live run.

| Setting | Purpose |
| --- | --- |
| `NFR_API_TOKEN` | Caller key; clients send `Authorization: Bearer <token>` |
| `NFR_LOCAL_ROOT` | Local output root when S3 is not configured |
| `NFR_S3_BUCKET`, `NFR_S3_PREFIX` | Optional S3 output destination |
| `NFR_CALLBACK_URL`, `NFR_CALLBACK_MAILING` | Optional emailer destination and mailing |
| `NFR_CALLBACK_TOKEN` | Optional bearer token on the outbound callback |
| `NFR_PRESIGN_TTL` | Download-link lifetime |
| `ANTHROPIC_API_KEY` | Provider credential required for live API runs |

Keep callbacks unset for a local development run unless you intend to send a notification. A local output destination does not prevent paid provider calls. The README's cron example describes one machine, not a verified schedule for all deployments.
