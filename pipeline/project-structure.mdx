The Pipeline intranet is a mixed PHP and React application. Most pages are traditional PHP scripts served by Apache, while newer screens are React apps built with Vite and embedded into PHP hosts. Understanding the folder layout helps you find the right file when adding a feature or fixing a bug.

## Top-level layout

├── assets/                     # Static images, fonts, jvectormap data

## Key folders

| Folder | What it holds | When you touch it |
| --- | --- | --- |
| `inc/` | Shared PHP includes: `auth.php`, `functions.php`, `roles.php`, `env.php`, and dozens of `ajax_search_*.php` helpers | Adding reusable PHP functions or AJAX endpoints |
| `Classes/` | PHP classes for Docuware integration, RSS feeds, image manipulation, and barcode generation | Working with document scanning or barcode labels |
| `react-src/` | React components and Vite entry points for modern screens | Building or editing React-based tools |
| `dist/` | Compiled JS bundles from Vite (created by `npm run compile:react`) | Never edit directly; rebuild from `react-src/` |
| `assets/` | Static theme assets, map data, and icon sets | Adding images or map layers |
| `js/` | Shared vanilla JS: search, datatable filters, camera, drag-and-drop | Adding global client-side behavior |
| `css/` | Global stylesheets including `isco.css` and theme CSS | Updating site-wide styling |
| `vendor/` | Composer-installed packages (PHPMailer, PhpSpreadsheet, etc.) | After running `composer install` |

## React build system

Modern screens live in `react-src/` and are compiled by Vite. The build configuration in `vite.config.js` defines one entry point per screen:

- `search.jsx` — Global search interface
- `knowledge_mgt.jsx` — Knowledge-management interface; distinguish this UI bundle from [Pip's separate knowledge API](/pip/api)
- `event_log.jsx` — Event logging
- `vendor_quote_review.jsx` — Vendor quote review
- `quote_builder.jsx` — Quote builder
- `dc_fab_queue.jsx` — DC fabrication queue
- `fab_dc_queue.jsx` — Fabrication DC queue
- `bin_label_print.jsx` — Bin label printing

Running `npm run compile:react` builds these into `dist/` as individual `.js` files. In local development, Vite watches `react-src/` and rebuilds automatically. In CI, `compile_react.yaml` builds and deploys the bundles to the Windows server.

## Configuration files

| File | Purpose |
| --- | --- |
| `composer.json` | PHP 8.2+ requirements: LDAP, ODBC, MySQLi, cURL, GD, plus PhpSpreadsheet and PHPMailer |
| `package.json` | Node 20 dependencies: React 19, Vite 7, Axios, TanStack Query, DataTables, ApexCharts, Tailwind Merge |
| `vite.config.js` | Vite root set to `react-src/`, output to `dist/`, rollup entry points for each React screen |

<Note>
  The `dist/` folder is generated and should not be committed. It is rebuilt on every deploy via the `compile_react.yaml` workflow.
</Note>
