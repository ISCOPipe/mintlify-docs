The MCP repositories expose employee, product, opportunity, quote/order, and Elasticsearch tools. They are separate services, not routes in Pipeline Services.

## Connect to the correct service

| Repository | HTTP path | Server key setting |
| --- | --- | --- |
| `elastic_mcp` | `/mcp/elastic_mcp` | `ELASTIC_MCP_KEY` |
| `employee_mcp` | `/employee-mcp/mcp` | `EMPLOYEE_MCP_KEY` |
| `product_mcp` | `/product-mcp/mcp` | `PRODUCT_MCP_KEY` |
| `opportunity_mcp` | `/opportunity-mcp/mcp` | `MCP_KEY` |
| `qovc_mcp` | `/qovc-mcp/mcp` | `MCP_KEY` |

Get the host and key through the approved environment configuration. The Elasticsearch, employee, and product services default to ports `9950`, `9952`, and `9954`, respectively. Binding to a network interface does not make a service safe for public access. Requests without the required key receive `401`.

All five HTTP handlers require `Authorization: Bearer <mcp-key>`, where the key matches that server's setting in the table. Use the capitalized `Bearer` scheme: the middleware matches it case-sensitively. A missing server key, missing header, or mismatched key returns `401`. This shared MCP key is not an Azure access token.

## Resolve an entity before querying its records

1. Inspect the service's schema or discovery tool. Do not assume that similarly named systems use the same field names.
2. Read `entity_resolution_contracts` where the schema provides it.
3. Map input fields with `fieldMap` and returned fields with `outputFieldMap`.
4. Resolve an exact identifier where possible. For a name, inspect the candidate list and its company or source context.
5. If several candidates remain, ask for a selection instead of choosing the first result.
6. Follow `nextTools` to query the resolved entity's records.

A person, company, or product name is not a reliable join key. Preserve the resolved identity across follow-up calls.

## Interpret each tool's output

- **Employee and product:** structured results include `items`, `count`, and `message`. Read the message when the list is empty or a query broadens.
- **Elasticsearch:** tool results can contain JSON as text. The `es_search` tool expects its query DSL as a JSON-encoded string, not an arbitrary nested argument.
- **Opportunity and QOVC:** discover the DAB-backed schema before building a query. Preserve exact company and source context when resolving records.
- **QOVC:** filters combine with AND. Pagination defaults to 25 rows and allows at most 100 per page. Quote-line product identity uses `productCode`.

Product tools normalize and broaden some searches. A lookup can fall back to a prefix match, so do not call every returned candidate an exact match. Work-order enrichment is opt-in; enable it only when the task needs that information.

## Add a client safely

1. Open the package directory listed below. Each has a committed npm lockfile.
2. Run `npm ci`, then obtain the service's development backend settings and MCP key through the approved configuration process. Keep local configuration untracked.
3. Run `npm run build`, then `npm start`. All five start scripts run `npx -y tsx src/server.ts`; starting may require network access to obtain `tsx`.
4. Configure the MCP client with the service's full HTTP path and `Authorization: Bearer <mcp-key>`.
5. Start with schema discovery and a read-only query against approved data.
6. Check status, result shape, and pagination before integrating the result into another system.

| Repository | Package directory from the repository root | Build and start |
| --- | --- | --- |
| `elastic_mcp` | `elastic_mcp/` | `npm run build`, then `npm start` |
| `employee_mcp` | `.` | `npm run build`, then `npm start` |
| `product_mcp` | `.` | `npm run build`, then `npm start` |
| `opportunity_mcp` | `.` | `npm run build`, then `npm start` |
| `qovc_mcp` | `.` | `npm run build`, then `npm start` |

These are start commands, not offline tests. The Elasticsearch test script calls its tool harness, and Product's `test:wet` exercises live search. Inspect external effects before running either.

Do not paste keys or customer records into example tool calls. A tool server's available methods are not a substitute for your permission to use the underlying records.
