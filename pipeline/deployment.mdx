Pipeline deploys automatically from GitHub Actions on a self-hosted runner. Each branch has its own docroot on a server, so pushing to a branch updates that environment.

## Branches and servers

| Branch | Server | Docroot folder |
| --- | --- | --- |
| `main` | Production | `pipeline` |
| `test` | Production | `test` |
| `bazooka`, `beachhead`, `roadblock`, `scarlett`, `shipwreck`, `wild_bill` | Development | Branch name |

`main` deploys when a pull request into it is closed. The other branches deploy on every push.

## Workflows

<AccordionGroup>
  <Accordion title="Deploy to Server (deploy.yaml)">
    SSHes into the target server, runs `git fetch`, and runs `npm ci` only when `package-lock.json` changed or `node_modules` is missing. It then runs `git reset --hard` to the branch, which also handles force pushes.
  </Accordion>

  <Accordion title="Deploy React (compile_react.yaml)">
    Runs when `react-src/`, `package.json`, `package-lock.json`, `vite.config.js`, or the workflow changes. It builds with Node 20 and `npx vite build`, packages `dist/`, copies it to the Windows server, and runs `deploy-react.ps1` to unpack it into `<DIR>/<docroot>/dist`.
  </Accordion>

  <Accordion title="Sync (sync.yaml)">
    When a pull request into `main` is closed, runs `sync-branches.py` to sync the staging branches with `main`.
  </Accordion>
</AccordionGroup>

## Feature-deployment guidance

The [ADO feature-deployment guide](https://dev.azure.com/ISCO-PIPE/af08c6ac-ebae-4d0a-bf50-811762d53dd2/_wiki/wikis/3688edc8-fba5-407c-926f-78e7f119e792?pagePath=%2FIT%20Development%20Documentation%2F_Project-Specific%2FAB9192%3A%20Feature%20Deployments), updated October 14, 2026, describes a separate PR-preview flow: non-draft PRs into `test` receive `https://<PR-number>.pipeline.isco-pipe.com`, and closing or drafting a PR removes its preview. It describes Git worktrees on the development server, Apache `VirtualDocumentRoot`, wildcard DNS, and a wildcard certificate.

That guide names `.github/workflows/feature_deploy.yml`, which was absent from the inspected `main` checkout and the `test` branch lookup on October 16, 2026. Do not assume this preview flow is available from the branch-per-environment workflows above. Confirm the workflow on the branch you use and its successful deployment before sharing a preview URL. The wiki's eventual move from `test` to `main` is a plan, not a confirmed trigger.

## Required repository secrets

Set these under **Settings > Secrets and variables > Actions** in `iscopipe/pipeline`:

| Secret | Purpose |
| --- | --- |
| `DIR` | Parent folder of the docroots, with no trailing backslash (for example `X:\server\www`) |
| `PROD_IP`, `DEV_IP` | Server addresses |
| `HOST_PORT` | SSH port |
| `SSH_USER`, `SSH_KEY` | SSH user and private key |

<Tip>
  To test a change safely, push it to one of the development branches first and verify it on that branch's subdomain before opening a pull request into `main`.
</Tip>
